## 2026-08-22 — Две тихие аварии, мониторинг, rich-форматирование, утечка токена

**Проблема:** две рубрики молчали месяцами, и ни один лог не сигналил об этом наружу.

- **Гайд экспата** не публиковался 12 воскресений подряд (31.05–16.08). Причина — материал id=5 (следующий по очереди) все эти недели оставался с пустым `body`, а бот при пустом теле писал `WARNING` в лог и выходил с кодом 0. Пропуск недели при неготовом материале — правильное поведение (лучше промолчать, чем постить пустоту), но у этого пропуска не было сигнала наружу: код 0 = «всё хорошо» для cron, WARNING в файле, который никто не читает, — это и есть отказ без сигнала.
- **Новости** не выходили 26 суток: 20.06–02.07 и 04.07–20.07. Причина — `claude -p` возвращал `rc=1`, а в лог писался только `stderr`. У этого CLI `stderr` при таких сбоях пуст — вся диагностика уходит в `stdout`, который никто не собирал. Лог показывал голое `[ERROR] Claude Code CLI error (rc=1):` без единого слова о причине.

**Сделано:**
- Догенерированы материалы гайда id 5–39 (35 штук) — все 39 материалов серии теперь заполнены и прошли валидацию.
- Добавлен мониторинг: `telegram_sender.py` пишет `heartbeats.json` после каждой успешной публикации (общая точка для всех ботов, обойти нечем). Новый `healthcheck.py` проверяет молчание каждой рубрики (пороги: 30 часов для дайджеста/новостей/урока, 8 недель для гайда) и запас контента (сколько дней/недель материалов осталось), при проблеме шлёт алерт в служебный чат (`telegram.ops_chat_id`, с фоллбэком на `test_chat_id`). Первый же прогон на реальных данных поймал именно ту аварию, ради которой сторож писался: «Гайд экспата: молчит 90 дней».
- Погодный дайджест переведён на rich-таблицы (`rich_render.py`): показатели таблицей, цитата с AQI, разделитель. Новости — на rich-статью: тот же конвертер плюс `article_image.py`, который скачивает заглавную картинку статьи во временный файл и удаляет его сразу после отправки. Эмпирически выяснено: в rich-сообщениях Telegram превью ссылки не генерируется вовсе — ни через `link_preview_options`, ни как-то иначе, поэтому картинку пришлось отдавать явно. Оба потока при неудаче rich-отправки откатываются на обычный `sendMessage` с текстом как раньше.

**Исправлено:**
- Ретраи телеграм-отправщика не срабатывали на 5xx — ретраились только сетевые исключения, серверные ошибки Telegram уходили без повторной попытки.
- Отказ AQI ронял весь погодный пост вместо того, чтобы просто убрать секцию воздуха — деградация была неполной.
- Цены бензина A95 и золота SJC были захардкожены и выдавались за сегодняшние при недоступности источника, без пометки и без даты. Добавлен `price_cache.json` с последним реально полученным значением и его датой.
- В обоих контентных ботах (новости, погода) не было защиты от повторного запуска — параллельный cron или ручной перезапуск во время работы предыдущего инстанса мог задвоить пост. Добавлена файловая блокировка (`*.lock`).
- Дедуп выбрасывал свежие новости из-за суффикса издателя в заголовках RSS («… — VnExpress International») — суффикс раздувал непересекающуюся часть при сравнении и валидные заголовки помечались как разные истории чаще, чем нужно.

**Найдено и требует внимания — токен бота в открытом виде:** в `logs/vietnamese.log` обнаружено 6 вхождений токена бота открытым текстом. Причина — `requests` при сетевой ошибке кладёт полный URL запроса (включая токен) в текст исключения, а код логировал исключение целиком. Логи вычищены, добавлена маскировка токена перед логированием. **Не закрыто: токен нужно перевыпустить через @BotFather** — он всё это время был в файле на диске в незашифрованном виде.

**Грабли:**
- «Бот вышел с кодом 0» не означает «всё в порядке» — это означает только «скрипт не упал». Для рубрик, которые публикуют по условию (гайд — только если материал готов), нужен отдельный сигнал об осмысленном пропуске, иначе тишина неотличима от штатной работы, пока кто-то не откроет логи руками.
- Не весь диагностический вывод CLI-инструментов идёт в `stderr` — `claude -p` при сбое молчит в `stderr` и говорит всё в `stdout`. Логировать нужно оба потока, а не только тот, что «положено» по конвенции.
- rich-сообщения Telegram не дают превью ссылки бесплатно — если разметке нужна иллюстрация, её нужно скачивать и прикладывать самим, готового автоматического поведения тут нет.

- Создан общий модуль `telegram_sender.py` для двух новых ботов (weather и news не трогаем)

- Atomic write через `.tmp` + `os.replace` для всех state-файлов
- State обновляется только после успешной отправки в Telegram
- `--dry-run` флаг во всех ботах для проверки форматирования без отправки
